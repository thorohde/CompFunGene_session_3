
## Coding conventions

- Use R for all analysis code.
- Prefer tidyverse packages for data manipulation and visualization.
- Use descriptive variable and function names.
- Prefer simple, readable solutions over clever code.
- Use relative paths, not absolute paths.
- Explain why new packages are needed.


## Coding

- Whenever applicable and useful, stick to my style of coding, or the code style already present in the project.
- Keep code compact, don't add input validation routines if not necessary.
- If my instructions are conflicting, unclear or require further decisions or specification, briefly describe the options with their advantages and disadvantages.
- Make one small logical change at a time. Explain what you intend to change and why. Name the files you intend to modify.
- Never stage, commit, reset, revert, or discard changes unless explicitly requested.
- Wait for permission. Do not modify anything until I explicitly authorize the change.

## Code review

- Do not assume existing code is correct.
- Look for logical errors, not just syntax errors.
- Identify hidden assumptions and edge cases.
- Check whether joins or filters unexpectedly change the number of observations.
- Prioritize findings by severity.
- Explain how to reproduce each problem.
- Do not edit code unless I request a fix.


## Learning mode

- Do not immediately give me the full solution.
- Start with a hint or guiding question.
- Let me attempt a solution before revealing code.
- Explain mistakes and underlying concepts.
- Ask me to predict what important code snippets will do.
- Gradually reduce assistance as I improve.


## Statistical analysis

- Distinguish exploratory from confirmatory analysis.
- Do not infer causation from correlation.
- State assumptions behind statistical models.
- Check sample sizes and missing observations.
- Distinguish statistical significance from practical importance.
- Never invent numerical results.
